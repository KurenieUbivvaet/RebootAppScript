# RebootAppScript

Ежедневный перезапуск приложения **«Ассистент»** (или любого другого `.exe`) по расписанию.
Скрипт запускается вместе с Windows, работает в фоне без окна консоли, сам завершает
приложение, выдерживает паузу и запускает его снова. Все действия пишутся в лог.

* Перезапуск каждый день в **00:00** (время настраивается).
* Автозапуск после перезагрузки компьютера или сервера.
* Работает без прав администратора в момент перезапуска: задача планировщика
  запускается с наивысшими правами, поэтому UAC не мешает.
* Не требует установленных библиотек Python: только сам Python 3.8+.
* Понятное управление через `control.bat` и установка одним файлом `install.bat`.
* Логи с ротацией, защита от второго экземпляра, повторные попытки запуска.

---

## Быстрая установка

1. Скачайте репозиторий (архивом или через Git) в любую папку.
   Путь может содержать пробелы и русские буквы.
2. Запустите **`install.bat`** (можно просто двойным щелчком — он сам запросит права
   администратора).
3. Дождитесь сообщения «Установка завершена».

`install.bat`:

* проверит и при необходимости установит Python 3.13 (через `winget`, а если его нет —
  скачает установщик с python.org и поставит в тихом режиме);
* проверит `config.json` и предложит исправить путь к приложению, если он не найден;
* зарегистрирует задачу автозапуска `RebootAppScript` в Планировщике заданий;
* запустит супервизор и покажет статус.

Проверить, что всё работает:

```bat
control.bat status
```

## Управление

Запустите **`control.bat`** без параметров — откроется меню:

```
1. Статус (задача, приложение, последний перезапуск)
2. Перезапустить "Ассистент" сейчас
3. Запустить супервизор
4. Остановить супервизор
5. Открыть config.json
6. Открыть лог
7. Установить / обновить автозапуск
8. Удалить автозапуск
0. Выход
```

Те же действия можно вызывать командами (удобно для ярлыков и скриптов):

| Команда | Что делает |
|---|---|
| `control.bat status` | состояние: приложение, супервизор, задача, последний перезапуск |
| `control.bat check` | проверка без перезапуска: конфигурация, план действий, статус |
| `control.bat restart` | перезапустить приложение прямо сейчас |
| `control.bat start` | запустить супервизор (задачу планировщика) |
| `control.bat stop` | остановить супервизор (приложение продолжает работать) |
| `control.bat config` | открыть `config.json` в Блокноте |
| `control.bat logs` | показать последние строки лога и открыть папку `logs` |
| `control.bat install` | запустить установку/обновление автозапуска |
| `control.bat uninstall` | удалить задачу автозапуска |

Действия, которым нужны права администратора, сами запросят UAC.

## Настройка `config.json`

Файл лежит рядом со `script.py` и читается при старте супервизора.
После изменения файла перезапустите супервизор (в меню `control.bat`: пункт 4, затем 3).

```json
{
  "target_time": "00:00",
  "process_name": "assistant.exe",
  "file_to_run": "C:\\Program Files (x86)\\Ассистент\\assistant.exe",
  "app_args": [],
  "timeout": 60,
  "kill_timeout": 30,
  "launch_retries": 3,
  "launch_retry_delay": 10,
  "launch_check_seconds": 20,
  "start_if_not_running": true,
  "startup_delay": 30,
  "log_level": "INFO",
  "window_position": "primary"
}
```

| Параметр | По умолчанию | Описание |
|---|---|---|
| `target_time` | `"00:00"` | Время ежедневного перезапуска, формат `"ЧЧ:ММ"` (например `"00:00"`, `"3:30"`). |
| `process_name` | `"assistant.exe"` | Имя процесса, который нужно завершить. Смотрите в Диспетчере задач. |
| `file_to_run` | путь к `assistant.exe` | Полный путь к файлу, который нужно запустить. Обратные слэши удваиваются. |
| `app_args` | `[]` | Дополнительные аргументы командной строки, например `["-silent"]`. |
| `timeout` | `60` | Пауза в секундах между завершением и запуском. |
| `kill_timeout` | `30` | Сколько секунд ждать фактического завершения процесса. |
| `launch_retries` | `3` | Сколько раз повторить запуск, если процесс не появился. |
| `launch_retry_delay` | `10` | Пауза между попытками запуска, секунды. |
| `launch_check_seconds` | `20` | Сколько секунд ждать появления **окна** после запуска. |
| `start_if_not_running` | `true` | Запускать приложение (и открывать окно) при старте супервизора, если оно не запущено. |
| `startup_delay` | `30` | Задержка после входа в систему, чтобы автозапуск приложения успел сработать. |
| `log_level` | `"INFO"` | `DEBUG`, `INFO`, `WARNING` или `ERROR`. |
| `window_position` | `"primary"` | `"primary"` — переносить главное окно на основной монитор; `"keep"` — не трогать позицию. Окна сеансов удалённого управления не затрагиваются. |

> JSON не поддерживает комментарии. Кавычки и запятые обязательны.
> Параметры, которых нет в файле, берутся по умолчанию.

## Как это работает

1. При входе пользователя в систему Планировщик заданий запускает задачу
   `RebootAppScript` с наивысшими правами. Задача стартует
   `pythonw.exe script.py --daemon` — без окна консоли и без запроса UAC.
2. Супервизор загружает `config.json`, ждёт `startup_delay` секунд и проверяет
   приложение. Если процесса нет — запускает его. Если процесс есть, но **главное окно
   не найдено** (служба подняла приложение в фоне), запускает `assistant.exe`, чтобы
   открыть интерфейс.
3. Далее он ждёт ближайшие `target_time` (по умолчанию 00:00). В нужный момент:
   * завершает процесс (`taskkill`, при необходимости — PowerShell);
   * ждёт фактического завершения, но не дольше `kill_timeout`;
   * выдерживает `timeout` секунд;
   * запускает приложение и ждёт появления **окна** (до `launch_retries` попыток).
4. Если служба «Ассистента» уже подняла фоновый процесс, скрипт всё равно откроет окно,
   а не сочтёт перезапуск завершённым. При `window_position: "primary"` главное окно
   переносится на основной монитор; окна удалённых сеансов не двигаются.
5. Если компьютер был в спящем режиме и пропустил время, перезапуск выполнится сразу
   после пробуждения.
6. Второй экземпляр супервизора запустить нельзя — он сразу завершится.

Все события пишутся в `logs\rebootapp.log` (ротация: 5 файлов по 5 МБ).
Текущее состояние — в `state.json` (создаётся автоматически).

### Автозапуск и серверы без входа пользователя

Задача создаётся с триггером **«При входе пользователя»** и работает в интерактивном
сеансе. Это важно для программ с интерфейсом: только так «Ассистент» будет виден
пользователю, а не спрятан в служебном сеансе.

Если сервер перезагружается и **никто не входит в систему**, приложение с интерфейсом
всё равно не сможет показаться. В этом случае включите автоматический вход
(`netplwiz`) или вход пользователя после перезагрузки — задача запустится сама.

Для приложений **без интерфейса** (служб) можно использовать режим `SYSTEM`, но
обычному GUI-приложению он не подходит.

## Проверка без ожидания полуночи

1. **`control.bat check`** — безопасная проверка: валидирует `config.json`, показывает
   план перезапуска и состояние задачи. Ничего не закрывает и не запускает.
2. **`control.bat status`** — должен показать «Супервизор: работает» и зарегистрированную
   задачу `RebootAppScript`.
3. **`control.bat restart`** — настоящий тестовый перезапуск: «Ассистент» закроется,
   через `timeout` секунд откроется снова. Сравните PID до и после, проверьте лог.
4. **Проверка расписания** (по желанию): временно поставьте в `config.json`
   `"target_time"` на 2–3 минуты вперёд, выполните `control.bat stop` и
   `control.bat start`, дождитесь срабатывания и посмотрите `logs\rebootapp.log`.
   Затем верните `"00:00"` и снова перезапустите супервизор.
5. **Проверка после перезагрузки**: перезагрузите компьютер, войдите в систему и
   выполните `control.bat status`. Супервизор должен запуститься сам, «Ассистент» —
   работать.

`install.bat` в конце сам показывает план ближайшего перезапуска.

## Логи и диагностика

* Лог: `logs\rebootapp.log` (рядом со скриптом).
* Быстрый просмотр: `control.bat logs`.
* Подробная диагностика: поставьте `"log_level": "DEBUG"` в `config.json`,
  перезапустите супервизор и повторите действие.
* Ручной запуск в консоли (для отладки): `script_start.bat` — откроется окно с логом,
  закройте его по `Ctrl+C`. Для работы перезапуска этот способ не нужен.

### Если что-то не работает

| Симптом | Что проверить |
|---|---|
| `Супервизор: не запущен` | Выполните `install.bat` или `control.bat start`. Посмотрите лог. |
| Задача есть, но перезапуска нет | Пользователь должен быть **в системе** (задача интерактивная). Проверьте `control.bat status`. |
| `Файл приложения не найден` | Исправьте `file_to_run` в `config.json` (обратные слэши удваиваются). |
| `Не удалось завершить процесс` | Запустите `install.bat` заново: задача должна работать с наивысшими правами. Проверьте, не защищено ли приложение антивирусом. |
| Приложение не запускается | Проверьте, что `file_to_run` запускается вручную. При необходимости добавьте аргументы в `app_args`. |
| Процесс есть, но окна нет | `control.bat status` покажет «Окно: НЕ НАЙДЕНО». Скрипт откроет окно при следующем старте/перезапуске; можно сразу выполнить `control.bat restart`. |
| Окно открывается на втором мониторе | В `config.json` установите `"window_position": "primary"` и перезапустите супервизор. |
| В логе `[WinError 5]` / «Отказано в доступе» | Недостаточно прав. Установите автозапуск через `install.bat` (не запускайте `script.py` вручную без администратора). |
| После смены `config.json` ничего не изменилось | Перезапустите супервизор: `control.bat stop`, затем `control.bat start`. |

## Удаление

```bat
uninstall.bat
```

Удаляет задачу автозапуска. Приложение и файлы скрипта остаются; логи и `state.json`
можно удалить по запросу. Папку проекта после этого можно удалить вручную.

## Состав репозитория

```
install.bat              установка: Python, проверка конфигурации, автозапуск
control.bat              меню и команды управления
uninstall.bat            удаление автозапуска
script.py                супервизор (стандартная библиотека Python)
config.json              настройки
tools\find_python.bat    поиск Python 3.8+ на компьютере
tools\RebootAppTask.ps1  регистрация задачи в Планировщике заданий
script_start.bat         запуск в консоли для диагностики
first_launch.bat         устаревшее имя, перенаправляет на install.bat
logs\                    логи (создаётся автоматически, в Git не попадает)
```

Требования: Windows 10/11 (или Windows Server 2016+), Python 3.8+.
Проверено на Windows 11 и Python 3.14.

### Обновление со старой версии

Старая версия требовала `schedule` и виртуальное окружение. Теперь внешние библиотеки
не нужны: `requirements.txt` и `.venv` можно удалить, `first_launch.bat` больше не нужен.

Если вы раньше создавали задачу в Планировщике **вручную** (например, «Запуск моего
скрипта»), удалите её — иначе будет запускаться второй супервизор. Новый скрипт
защищён от дублирования, но лишнее окно консоли ни к чему.

## Для разработчика

Прямые команды `script.py`:

```bat
python script.py --status
python script.py --check
python script.py --dry-run
python script.py --restart-now --config config.json
python script.py --daemon
python script.py --init-config
```

Коды выхода `--check`: `0` — всё в порядке, `2` — ошибка в `config.json`,
`4` — конфигурация корректна, но файл приложения не найден.

EXE-файл не требуется: `install.bat` сам устанавливает Python, а задача запускает
`pythonw.exe`, поэтому окно консоли не появляется.
